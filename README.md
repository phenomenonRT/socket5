# SOCKS5 Anti-DPI Suite (Server-Side Bypass)

> 🛡️ **Серверный комплекс обхода блокировок SOCKS5 в России (ТСПУ / РКН)**  
> Работает со **стандартными SOCKS5 клиентами** (Telegram, браузеры, игры, боты, парсеры, curl).  
> **На клиенте ничего менять и устанавливать не нужно!**

> Данный комплекс решает исключительно одну прикладную задачу — **обход блокировок ТСПУ / РКН на этапе рукопожатия соединения**.  
> По уровню защиты и конфиденциальности данных он **полностью идентичен стандартному SOCKS5 и НЕ является VPN**:  
> * **Шифрование канала связи отсутствует**: трафик между вашим устройством и сервером передается в открытом виде (протокол SOCKS5 не шифрует передаваемые данные).  
> * **Данные защищены ТОЛЬКО тогда**, когда само клиентское приложение использует сквозное шифрование (например, сайты по протоколу **HTTPS** в браузере или встроенный защищенный протокол **MTProto** в Telegram).  
> * При открытии незашифрованных ресурсов (**обычный HTTP**, открытый TCP) ваш интернет-провайдер и узлы на пути могут видеть передаваемые данные.  
> * Если вам требуется полная криптографическая изоляция всего интернет-трафика устройства от оператора связи — используйте полноценный VPN (AmneziaWG, WireGuard, VLESS/Reality).

## 🧠 Какие технологии обхода блокировок здесь применены?

Обычный SOCKS5 блокируется ТСПУ мгновенно из-за открытого незашифрованного рукопожатия. В этом проекте реализован комплекс взаимодополняющих серверных техник:

### 1. Двухэтапный TCP Window Clamping (Нарезка пакетов на 2 байта)
* **Проблема:** Клиент отправляет Greeting `\x05\x01\x00` (3 байта) или Connect Request `\x05\x01\x00\x03...`. ТСПУ по сигнатуре `05 01 00` сразу сбрасывает соединение (TCP RST).
* **Решение:** Серверный демон `socks5-winclamp` перехватывает исходящие пакеты на уровне `libnetfilter_queue` и уменьшает размер TCP-окна до **2 байт**:
  1. **Фаза 1 (Handshake):** На исходящем `SYN-ACK` окно зажимается до 2 байт. Клиент вынужден разделить SOCKS5 Greeting: `\x05\x01` (пакет 1) и `\x00` (пакет 2).
  2. **Фаза 2 (Connect Request):** На ответе сервера о выборе метода (`\x05\x00`) или об успешной авторизации логин/пароль по RFC 1929 (`\x01\x00`) окно снова зажимается до 2 байт. Клиент вынужден разделить Connect Request: `\x05\x01` (пакет 1) и `\x00\x03...` (пакет 2).
* **Результат:** Сетевой стек операционной системы клиента (Windows, Android, iOS, macOS, Linux) **принудительно нарезает** свои запросы:
  * ТСПУ видит только разрозненные фрагменты пакетов (`05 01`, затем `00`), сигнатура `05 01 00` отсутствует в DPI-буфере, и фильтр **пропускает трафик**!

```
[Клиент (РФ)]                                              [Сервер VPS]
      │ ──── 1. TCP SYN ──────────────────────────────────────> │
      │ <─── 2. TCP SYN-ACK (Window Size = 2 байта!) ────────── │ (winclamp зажимает окно)
      │ ──── 3. TCP ACK (Handshake завершен) ─────────────────> │
      │                                                         │
      │ Стек TCP клиента вынужден распилить Greeting:           │
      │ ──── 4. Пакет 1: \x05\x01 (2 байта) ──────────────────> │ [ТСПУ: 05 01] -> Пропуск!
      │ <─── 5. TCP ACK (окно раскрывается) ─────────────────── │
      │ ──── 6. Пакет 2: \x00 (1 байт) ───────────────────────> │ [ТСПУ: 00]    -> Пропуск!
      │                                                         │
      │ Сервер отвечает методом/авторизацией (Window = 2):       │
      │ <─── 7. Ответ авторизации \x01\x00 (Window = 2 байта!) ── │ (winclamp зажимает окно)
      │ ──── 8. Connect Req Часть 1: \x05\x01 (2 байта) ──────> │ [ТСПУ: 05 01] -> Пропуск!
      │ <─── 9. TCP ACK ─────────────────────────────────────── │
      │ ──── 10. Connect Req Часть 2: \x00\x03... ────────────> │ [ТСПУ: 00 03...] -> Пропуск!
      │                                                         │
      │ Соединение установлено, дальше трафик идет на полной скорости! │
```

### 2. Мультипортовое зеркалирование (Port Multiplexing)
* Провайдеры часто выборочно замедляют или блокируют порт `1080`.
* В режиме **«Ультра»** сервер через `iptables REDIRECT` зеркалирует входящий трафик сразу на нескольких системных и доверенных портах:
  * **443** (HTTPS — наивысший приоритет у всех операторов)
  * **8443** (Альтернативный HTTPS)
  * **2083** (SSL-порт cPanel / Cloudflare)
  * **53** (DNS по TCP — часто полностью открыт в отелях и публичных Wi-Fi)
  * **1080** (Стандартный SOCKS5)
* Вы можете подключиться к **любому** из этих портов с одними и теми же учетными данными!

---

### 3. Anti-Active-Probing & Smart SYN Limiter
* **Защита от зондов РКН:** Когда ТСПУ подозревает прокси, оно отправляет зондирующие бот-запросы для выявления SOCKS5-сервера. Наш сервер требует строгую авторизацию и сбрасывает некорректные сканирующие пакеты, не раскрывая себя сканерам.
* **SYN Limiter:** Как и в проекте *MTProxyL Reanimator*, отсекает паразитный флуд повторных SYN-запросов клиента Telegram, что исключает попадание IP в бан-лист провайдера и обеспечивает **мгновенное подключение** без зависаний.

---

### 4. BBR v2/v3 & Zero Segmentation Coalescing (TSO/GSO Offload)
* Отключение аппаратного слияния пакетов на сетевой карте (`ethtool tso off gso off gro off`), чтобы ядро не склеивало нарезанные пакеты перед отправкой.
* Включение алгоритма контроля перегрузки **BBR** от Google для минимизации задержек и пинга при высоких потерях пакетов.

## 📱 Как подключиться с устройств

### 1. Telegram (iOS, Android, Desktop)
Используйте ссылку в один клик:
```text
tg://socks?server=ВАШ_IP&port=1080&user=proxyuser&pass=ПАРОЛЬ
```
Или с маскировкой под HTTPS-порт:
```text
tg://socks?server=ВАШ_IP&port=443&user=proxyuser&pass=ПАРОЛЬ
```

### 2. В браузере (Chrome / Edge / Firefox)
Установите расширение **Proxy SwitchyOmega** или **FoxyProxy**:
* Протокол: `SOCKS5`
* Сервер: `IP_СЕРВЕРА`
* Порт: `443` или `1080`
* Имя пользователя и пароль

### 3. Проверка через cURL в терминале
```bash
curl -x socks5h://proxyuser:ПАРОЛЬ@IP_СЕРВЕРА:1080 https://api.ipify.org
```

## 🛠️ Управление сервером (`socks5-control`)

После установки доступна интерактивная панель управления:

```bash
socks5-control
```

Или прямыми командами:
* `socks5-control status` — Проверить статус Dante, winclamp и счетчики пакетов iptables
* `socks5-control info` — Показать IP, порты, логин, пароль и ссылки
* `socks5-control qr` — Показать ASCII QR-код для мгновенного добавления в Telegram с экрана
* `socks5-control logs` — Просмотр логов в реальном времени
* `socks5-control passwd <новый_пароль>` — Быстрая смена пароля
* `socks5-control restart` — Перезапуск всех служб
